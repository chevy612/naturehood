# Internationalization (i18n)

Naturehood uses [`next-intl`](https://next-intl.dev) with App Router locale routing.

## Locales

| Code | Language | URL |
|------|----------|-----|
| `en` | English (default) | `/…` (no prefix) |
| `zh-Hant` | Traditional Chinese | `/zh-Hant/…` |
| `zh-Hans` | Simplified Chinese | `/zh-Hans/…` |

Locale preference is remembered via the `next-intl` cookie and negotiated from `Accept-Language` when no cookie is set. English is the fallback.

## Where messages live

- `messages/en.json`
- `messages/zh-Hant.json`
- `messages/zh-Hans.json`

Namespaces group UI areas (`Nav`, `Home`, `Auth`, `Platform`, `Common`, …).

## Adding a new string

1. Add the key to **all three** JSON files under the right namespace (keep key paths identical).
2. In a Server Component: `const t = await getTranslations('Namespace')` then `{t('key')}`.
3. In a Client Component: `const t = useTranslations('Namespace')` then `{t('key')}`.
4. For links and redirects that should keep the active locale, import `Link`, `redirect`, `useRouter`, and `usePathname` from `@/i18n/navigation` (not `next/link` / `next/navigation`).

### Example

```tsx
// messages/en.json → { "Common": { "save": "Save" } }
const t = useTranslations('Common');
<button>{t('save')}</button>
```

## Routing / auth

- Pages live under `app/[locale]/…`. API routes stay at `app/api/` (not localized).
- `proxy.ts` runs `next-intl` middleware, then Supabase session refresh (`lib/supabase/middleware.ts`), which strips the locale prefix before auth path checks and re-applies it on redirects.

## Language switcher

`app/components/layout/language-switcher.tsx` — used in marketing nav/footer and the platform sidebar. It calls `router.replace(pathname, { locale })` so the current path is preserved.

## Server redirects

Prefer `import { redirect } from '@/i18n/redirect'` in Server Components and Server Actions. It resolves the active locale and calls next-intl’s `redirect({ href, locale })`.
